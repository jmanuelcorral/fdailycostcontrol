# fdailyCostControl — Azure Cost Monitoring Function

Azure Function (Python v2) that monitors daily Azure costs per Resource Group and sends alerts via webhook to Pandora FMS when configured thresholds are exceeded.

## Execution Flow

Every 5 minutes, the function executes the following flow:

1. **Load configuration**: Reads environment variables `AZURE_SUBSCRIPTION_ID`, `COST_MONITOR_CONFIG`, `WEBHOOK_ENDPOINTS`, and `ALERT_COOLDOWN_MINUTES`.
2. **Authentication**: Initializes `DefaultAzureCredential()` (uses Managed Identity in Azure or Service Principal locally).
3. **For each configured Resource Group**:
   - **Cost query**: Calls Azure Cost Management API for today’s accumulated cost (00:00 UTC → now), filtered by Resource Group.
   - **Threshold evaluation**: Compares cost to configured `threshold`.
   - **If threshold exceeded**:
     - **Cooldown check**: Checks Azure Table Storage for recent alerts for that RG (within cooldown period).
     - **Send alert**: If no active cooldown, builds alert payload and sends to all Pandora FMS endpoints.
     - **Record**: If at least one endpoint responds successfully (HTTP 2xx), records the alert in Table Storage.
4. **Summary**: Logs total alerts sent, skipped due to cooldown, and errors.

## Modules

### `function_app.py` — Orchestrator

- **Timer trigger**: CRON expression `0 */5 * * * *` (every 5 minutes).
- **`_load_json_env(var_name)`**: Utility to parse environment variables containing JSON arrays.
- **`timer_trigger()`**: Main function orchestrating the above flow.

### `modules/cost_client.py` — Cost Management Client

- **`get_daily_cost(credential, subscription_id, resource_group) -> float`**
  - Uses `azure-mgmt-costmanagement` SDK to query the API.
  - Builds a `QueryDefinition` of type `ActualCost` with custom timeframe (today).
  - Filters by Resource Group using `QueryFilter` with `In` operator.
  - Groups by `ResourceGroup` and sums total cost (`Sum` of `Cost`).
  - Returns `0.0` if no cost data.

### `modules/webhook_notifier.py` — HTTP Notifier

- **`send_alert(endpoints_config, alert_data) -> list`**
  - Iterates over all configured endpoints.
  - Supports HTTP **POST** (JSON body) and **GET** (query parameters).
  - Each endpoint can have custom headers (e.g., `Authorization`).
  - Handles individual endpoint errors without blocking others.
  - 30s timeout per request.
  - Returns a list of results with success/failure per endpoint.

- **`build_alert_data(...) -> dict`**
  - Builds the alert payload with all relevant fields.

### `modules/alert_tracker.py` — Cooldown Control

- **`should_send_alert(resource_group, cooldown_minutes) -> bool`**
  - Checks the `CostAlertTracker` table in Azure Table Storage.
  - Partitioned by date (`YYYY-MM-DD`), row key by resource group.
  - If last alert was less than `cooldown_minutes` ago, returns `False`.
  - On error, applies "fail open" (allows alert).

- **`record_alert_sent(resource_group, current_cost, threshold)`**
  - Records/updates entity in Table Storage with timestamp and cost data.
  - Uses `upsert_entity` to create or overwrite entry.

## Configuration

All configuration is managed via **environment variables** (App Settings in Azure, `local.settings.json` locally).

### Required Variables

| Variable | Type | Description |
|---|---|---|
| `AZURE_SUBSCRIPTION_ID` | `string` | Azure subscription ID to monitor |
| `COST_MONITOR_CONFIG` | `JSON array` | List of Resource Groups with thresholds |
| `WEBHOOK_ENDPOINTS` | `JSON array` | List of Pandora FMS endpoints |

### Optional Variables

| Variable | Type | Default | Description |
|---|---|---|---|
| `ALERT_COOLDOWN_MINUTES` | `integer` | `60` | Minimum minutes between alerts for same RG |
| `AzureWebJobsStorage` | `string` | `UseDevelopmentStorage=true` | Storage Account connection string (for Table Storage and runtime) |

### Local Development Variables (Service Principal)

| Variable | Description |
|---|---|
| `AZURE_TENANT_ID` | Azure AD tenant ID |
| `AZURE_CLIENT_ID` | App Registration ID |
| `AZURE_CLIENT_SECRET` | App Registration secret |

### `COST_MONITOR_CONFIG` Format

```json
[
  {
    "resource_group": "rg-production",
    "threshold": 50.0,
    "currency": "EUR"
  },
  {
    "resource_group": "rg-staging",
    "threshold": 20.0,
    "currency": "EUR"
  },
  {
    "resource_group": "rg-dev",
    "threshold": 10.0,
    "currency": "EUR"
  }
]
```

| Field | Type | Required | Description |
|---|---|---|---|
| `resource_group` | `string` | Yes | Resource Group name to monitor |
| `threshold` | `float` | No (default: 0.0) | Maximum allowed daily cost |
| `currency` | `string` | No (default: EUR) | Currency for alert payload |

### `WEBHOOK_ENDPOINTS` Format

```json
[
  {
    "url": "https://pandora.mycompany.com/api/webhook/cost-alert",
    "method": "POST",
    "headers": {
      "Authorization": "Bearer my-secret-token",
      "X-Custom-Header": "value"
    }
  },
  {
    "url": "https://pandora.mycompany.com/api/alert?type=cost",
    "method": "GET"
  }
]
```

| Field | Type | Required | Description |
|---|---|---|---|
| `url` | `string` | Yes | Webhook endpoint URL |
| `method` | `string` | No (default: POST) | HTTP method: `POST` or `GET` |
| `headers` | `object` | No | Additional HTTP headers (e.g., Authorization) |

## Authentication

The function uses `DefaultAzureCredential` from `azure-identity`, which authenticates in this order:

1. **Environment variables** (`AZURE_TENANT_ID`, `AZURE_CLIENT_ID`, `AZURE_CLIENT_SECRET`) — used for local development.
2. **Managed Identity** — used automatically when the Function App has an assigned identity in Azure.
3. **Azure CLI** — if an `az login` session is active (useful for local debugging).
4. **Visual Studio Code** — if authenticated in VS Code.

### Required Permissions

The identity (Service Principal or Managed Identity) needs the role:

- **`Cost Management Reader`** at the **subscription** scope.

Command to assign the role to the Function App’s Managed Identity:

```bash
az role assignment create \
  --assignee <function-app-managed-identity-object-id> \
  --role "Cost Management Reader" \
  --scope /subscriptions/<subscription-id>
```

## Duplicate Alert Control (Cooldown)

Since the function runs every 5 minutes, without cooldown it would send an alert every 5 minutes while the cost exceeds the threshold. The `alert_tracker.py` module solves this:

- Uses **Azure Table Storage** (`CostAlertTracker` table) to persist the timestamp of the last alert per Resource Group and day.
- Before sending an alert, checks if at least `ALERT_COOLDOWN_MINUTES` have passed since the last.
- If cooldown not expired, alert is skipped and logged.
- If Table Storage is unavailable, policy is "fail open": alert is sent anyway.

### Table Structure

| PartitionKey | RowKey | ResourceGroup | LastAlertTime | CurrentCost | Threshold |
|---|---|---|---|---|---|
| 2026-02-20 | rg-production | rg-production | 2026-02-20T14:30:00 | 55.2341 | 50.0 |

## Alert Payload

The JSON sent to webhooks contains:

```json
{
  "alert_type": "azure_cost_threshold_exceeded",
  "resource_group": "rg-production",
  "current_cost": 55.2341,
  "threshold": 50.0,
  "currency": "EUR",
  "subscription_id": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "exceeded_by": 5.2341,
  "exceeded_by_percent": 10.47,
  "timestamp": "2026-02-20T14:35:22.123456Z",
  "date": "2026-02-20"
}
```

| Field | Description |
|---|---|
| `alert_type` | Alert type (always `azure_cost_threshold_exceeded`) |
| `resource_group` | Resource Group name that exceeded the threshold |
| `current_cost` | Accumulated cost for the current day |
| `threshold` | Configured threshold |
| `currency` | Configured currency |
| `subscription_id` | Azure subscription ID |
| `exceeded_by` | Absolute difference (cost - threshold) |
| `exceeded_by_percent` | Percentage exceeded over threshold |
| `timestamp` | Exact alert time (ISO 8601 UTC) |
| `date` | Evaluated day |

For **GET** endpoints, these fields are sent as query parameters in the URL.

## Azure Deployment

### Option 1: Automated Script (recommended)

The `deployment/deploy.ps1` script automates infrastructure creation:

1. Creates Resource Group.
2. Creates Storage Account.
3. Creates Function App (Consumption plan, Linux, Python 3.11).
4. Enables Managed Identity.
5. Assigns "Cost Management Reader" role to Managed Identity.
6. Creates Service Principal for local dev / CI/CD.
7. Configures App Settings.
8. Deploys code.

```powershell
cd deployment

.\deploy.ps1 `
    -SubscriptionId "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx" `
    -ResourceGroupName "rg-cost-control" `
    -FunctionAppName "func-daily-cost-control" `
    -StorageAccountName "stcostcontrol001" `
    -CostMonitorConfig '[{"resource_group":"rg-production","threshold":50.0,"currency":"EUR"}]' `
    -WebhookEndpoints '[{"url":"https://pandora.example.com/webhook","method":"POST","headers":{"Authorization":"Bearer xxx"}}]'
```

#### Script Parameters

| Parameter | Required | Default | Description |
|---|---|---|---|
| `SubscriptionId` | Yes | — | Subscription to deploy infrastructure |
| `ResourceGroupName` | Yes | — | Resource Group name for Function App |
| `Location` | No | `westeurope` | Azure region |
| `FunctionAppName` | Yes | — | Function App name (globally unique) |
| `StorageAccountName` | Yes | — | Storage Account name (3-24 chars, lowercase/numbers) |
| `ServicePrincipalName` | No | `sp-fdailyCostControl-local` | Service Principal name |
| `CostMonitorConfig` | No | — | JSON with RGs to monitor |
| `WebhookEndpoints` | No | — | JSON with Pandora FMS endpoints |
| `AlertCooldownMinutes` | No | `60` | Alert cooldown |
| `MonitoredSubscriptionId` | No | = SubscriptionId | If monitored subscription differs |

### Option 2: Manual Deployment

```bash
# 1. Deploy Function App
func azure functionapp publish <function-app-name>

# 2. Set environment variables (App Settings)
az functionapp config appsettings set \
  --name <function-app-name> \
  --resource-group <function-rg> \
  --settings \
    AZURE_SUBSCRIPTION_ID="xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx" \
    COST_MONITOR_CONFIG='[{"resource_group":"rg-production","threshold":50.0,"currency":"EUR"}]' \
    WEBHOOK_ENDPOINTS='[{"url":"https://pandora.example.com/webhook","method":"POST","headers":{"Authorization":"Bearer xxx"}}]' \
    ALERT_COOLDOWN_MINUTES="60"

# 3. Assign Cost Management Reader role to Managed Identity
IDENTITY_ID=$(az functionapp identity show --name <function-app-name> --resource-group <rg> --query principalId -o tsv)
az role assignment create \
  --assignee $IDENTITY_ID \
  --role "Cost Management Reader" \
  --scope /subscriptions/<subscription-id>
```

### Verification

- Check logs in **Application Insights** or with `func azure functionapp logstream <name>`.
- To force a test alert, set a very low `threshold` (e.g., `0.01`).

## Local Development

### Requirements

1. **Python 3.11+**
2. **[uv](https://docs.astral.sh/uv/)** — package and environment manager.
3. **Azure Functions Core Tools** (`func`)
4. **Azurite** (local Storage emulator) — needed for Table Storage and runtime.
5. A **Service Principal** with Cost Management Reader permissions (created by `deploy.ps1` or manually), or an active `az login` session.

### Steps

```bash
# 1. Install uv (if not installed)
#    Windows:  powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
#    macOS/Linux:  curl -LsSf https://astral.sh/uv/install.sh | sh

# 2. Create virtual environment and install dependencies (prod + dev)
uv sync

# 3. Activate virtual environment
#    Windows (PowerShell):  .venv\Scripts\Activate.ps1
#    Windows (CMD):         .venv\Scripts\activate.bat
#    macOS/Linux:           source .venv/bin/activate

# 4. Configure local.settings.json with real values
#    (or copy .env.example and rename)

# 5. Start Azurite (in another terminal)
azurite --silent

# 6. Run tests
uv run pytest tests/ -v

# 7. Run the function locally
func start
```

### Dependency Management with uv

Dependencies are defined in `pyproject.toml`. `requirements.txt` is generated automatically for Azure Functions deployment (still required for remote build).

```bash
# Add a production dependency
uv add <package>

# Add a development dependency
uv add --group dev <package>

# Upgrade all dependencies
uv lock --upgrade
uv sync

# Regenerate requirements.txt before deploying
uv export --no-hashes --no-dev --no-emit-project -o requirements.txt
```

### Tip: Force Immediate Execution

Temporarily set `run_on_startup=True` in `function_app.py` to execute the function on startup without waiting for the timer.

## Troubleshooting

| Problem | Possible Cause | Solution |
|---|---|---|
| `AZURE_SUBSCRIPTION_ID is not configured` | Environment variable not set | Set in `local.settings.json` or App Settings |
| `Invalid JSON in 'COST_MONITOR_CONFIG'` | Malformed JSON in variable | Validate JSON (double quotes, correct escaping) |
| `Error querying cost for RG` | Missing permissions or RG does not exist | Check Cost Management Reader role and RG name |
| `All webhook endpoints failed` | Incorrect URLs or Pandora not accessible | Check URLs and network connectivity |
| `Alert skipped: last alert was X min ago` | Cooldown active (expected behavior) | Reduce `ALERT_COOLDOWN_MINUTES` or wait |
| `Could not create table 'CostAlertTracker'` | Azurite not running (local) or Storage not accessible | Start Azurite or check `AzureWebJobsStorage` |
| `Failed to initialize Azure credential` | Credentials not configured | Check `AZURE_TENANT_ID`, `AZURE_CLIENT_ID`, `AZURE_CLIENT_SECRET` (local) or Managed Identity (Azure) |
